# Nightly raid cap and target-less raiders (2026-11-26)

Branch `raid-cap-and-exit` (off `main` at c470a01). Not pushed.

## Root cause (confirmed)
Found while investigating the growing autosaves (`AUTOSAVE-2026-11-26.md` on branch `autosave-rotation`), and reproduced
here against the unpatched code (c470a01) with the "E" scenario of the new test: a 160 world (seed 7), no soldiers, mobs
ignore the player, raids on, 26 game days.

- The Town Center fell on night 1. From then on `raidMarchGoal` returned `null` for every group ("nothing targetable:
  hold position") and `marchRaidGroup` simply returned: groups stayed `marching` forever and never dissolved.
- Raiders that had already been released from their group (contact) with nothing left to attack also stood still for
  ever (`updateMob` with no target just returns).
- `sim.ts` still spawned a nightly raid for clan 0 every day even without a Town Center or anything else to attack.

Day-end raid groups / raid mobs on the unpatched code:
`0/2 1/4 2/7 3/10 4/14 5/18 7/23 8/27 9/31 11/36 13/41 14/47 16/53 18/59 20/66 22/73 24/81 26/89 28/97 30/106 32/115
34/125 36/135 38/145 40/156 42/167`. Save on day 14: 99.1 KiB (20 groups, 66 raid mobs, `mobs` 46.7 KiB); day 25:
185.4 KiB (42 groups, 167 raid mobs, `mobs` 111.8 KiB): +86 KiB in 11 days (~7.8 KiB/day, of which `mobs` ~5.9 KiB/day).
That matches the autosave investigation (44 groups / 192 raid mobs by day 25 on a 1024 world, ~5.7 KB/day in `mobs`,
~1.7 KB/day in `raidGroups`).

With the fix, the same scenario: `0/2` on day 0, then `0/0` every day; the saves on days 14 and 25 are identical in size
(41.5 KiB, 0 groups, 0 raid mobs).

## Rule 1: one nightly raid at a time, per clan
- Raids are already per clan (`sim.ts` runs `spawnRaid` once per clan with a Town Center, clan 0 always unless Solo), so
  the cap is **per clan**.
- `spawnRaid` now tags each of its groups (`RaidGroup.raidClan`) and each of its mobs (`Mob.raidClan`, deserters who join
  the horde included) with the clan it was sent against. The tag stays on a mob after its group breaks up. Both fields are
  optional (old saves, camp raids and Creative groups have none); no save-format bump.
- `nightlyRaidActive(clanId)` (raids.ts) is true while any raid group, live mob (hp > 0) or parked mob carries that
  clan's tag. `sim.ts` skips that clan's `spawnRaid` while it is true. The raid's size / budget formula is unchanged.
- The day is still marked as done (`raidSpawnedForDay`): a skipped night is skipped, not deferred to later that day.
- Camp raids (`spawnCampRaids`), warbands and the `spawnRaidNow` / `spawnRaidGroup` test hooks are not capped and are
  called exactly as before.

## Rule 3: no raid when there is nothing to attack
`raidTargetExists()` (raids.ts) is the single "target-less" test. It is true while there is
- a standing Town Center (any clan) that is not warded, or
- an unwarded damageable building from `buildingTargetCandidates()` (houses, workshops, towers ...; walls, gates, moats
  and fences are not targets in their own right; NPC-site buildings are excluded, as they already were for mobs).

Guards, militia and players are not counted (they move about, and a raider already fighting one keeps fighting it). It is
cached for one second and recomputed at once when a building changes (`buildingTargetsDirty`) or the number of Town
Centers changes, so the cost is at most one scan of the building list per second, and usually one Town Center check.

`sim.ts` spawns the nightly raid only when `raidTargetExists() && !nightlyRaidActive(clan.id)`.

## Rule 2: raiders with no target leave
Detection, precisely:
- **A group** (`marchRaidGroup`): `raidMarchGoal(leader)` returned `null` **and** `raidTargetExists()` is false. A null goal
  while targets still exist (for example the per-tick building-pick budget ran out) keeps the old behaviour (hold this
  tick, try again).
- **A released raider** (`updateMob`, a mob with a `regimentId` from a raid group and no `siteId` / `warbandId`): it has no
  target after the normal re-pick (no guard / player in aggro range, no building found) **and** `raidTargetExists()` is
  false. A siege engine raider (ram, catapult), which only ever attacks buildings, leaves as soon as
  `raidTargetExists()` is false.
- A target that is only unreachable (walls, gates, a moat in the way) is **not** target-less: the building still exists,
  so `raidTargetExists()` stays true and the raiders keep breaching as before.

Exit: the existing routed-raid "leave" tactic is reused (`startRaiderLeave`, raids.ts): target cleared,
`tactic = "leave"`, the flee point is the nearest map edge (`fleeEdgePoint` from the mob's own position) and
`leaveUntilTick = now + RAID_LEAVE_MAX_TICKS` (60 s, the value routed raiders already use). `mobTactic` walks it there and
despawns it on the edge, at the flee point, or at the deadline, whichever comes first. A group leaving releases all its
members into this state and its `raidGroups` record is deleted at once (`leaveRaidGroup`, one toast "Finding nothing
left to plunder, the raiders withdraw", rate-limited like the rout toast).
- Leaving raiders count as "still active" for rule 1 until they despawn (at most 60 s), then the next night may raid
  again (if there is a target).
- Interiors: mobs never enter building interiors; a hero inside one is not a target, which is the normal rule.
- Cold chunks: a raid group is a chunk anchor, so grouped raiders are never parked. A released raider that is leaving, or
  any idle nightly raider (`raidClan` set, no target), that drifts into a COLD chunk is now despawned instead of parked
  (a parked mob never ticks, so it would never finish leaving and would block rule 1 for ever). This also applies to other
  "leave" mobs (routed raids, broken camp guardians): they had the same leak.
- Save/load: `tactic`, `fleeX/Y` and `leaveUntilTick` are ordinary mob fields and were already saved; a leaving raider
  resumes leaving with the same deadline after a load. No save-format change.

## Open points
- A raider that can never reach anything (an island, a pocket the breach search cannot open) while the colony still has
  buildings is not target-less, so it stays, and under rule 1 it blocks that clan's nightly raids until it dies. That
  is the rule as specified; a stranded-raider timeout would be a separate decision.
- Camp raids (`spawnCampRaids`) are not capped. They go through the same group code, so they now leave too when
  nothing is left to attack. Idle camp raiders that drift into a COLD chunk are still parked as before (they are not
  nightly raiders); only "leave" mobs and nightly raiders are dropped there.
- `leaveUntilTick` is not shifted by the load-time day-length migration (`aggroTick` is); with a changed day length a
  leaving raider's 60 s deadline may end early or late after loading. Harmless.
